# 04 — APP FLOW

## Homepage (`/`)

**File**: `public/index.html`  
**Server handling**: Pre-built at boot via `buildHomeHtml()` then served with per-request nonce injection. `Cache-Control: no-store` (nonce changes every request).

**Page sections**:
1. Navigation bar (logo, tool dropdowns, auth chip)
2. Hero section (headline, subheadline, CTA)
3. Tool grid (all 43+ tools grouped by category, rendered from `TOOLS` array)
4. Trust section (file count, privacy pledge, speed claim)
5. FAQ / feature highlights
6. Footer (links to legal, blog, contact)

**JavaScript loaded**: `home.js`, `auth-ui.js`, `tools-config.js`, `i18n.js`, runtime bundles (deferred)

## Tool Upload Page (`/:slug`)

**File**: `public/tool.html` (shared shell)  
**Server handling**: `buildHtml(slug, TOOL_HTML, 'upload')` injects per-tool SEO metadata (title, canonical, description, OG, Twitter, JSON-LD schemas: SoftwareApplication + FAQPage + HowTo + BreadcrumbList).

**Step flow controlled by**: `tool-page.js` reading `window.__STEP`

### Upload Step Sequence

```
1. tool-page.js resolves tool ID from URL slug
2. Renders step 1 (upload zone + tool options sidebar)
3. User selects/drops file(s)
4. Client validates: file type, file size (guest: 60 MB, free: 200 MB)
5. For single-PDF tools: PageOrganizer.open() mounts grid asynchronously
6. renderPreviewStep() transitions to step 2
```

**DOM elements injected by tool-page.js**:
- `#files-list`: File thumbnail row(s)
- `#page-organizer`: PageOrganizer grid (for PAGE_LEVEL_TOOLS)
- `#opt-*`: Tool option inputs (degrees, range, etc.)
- `#process-btn`: Triggers processFiles()

## Preview / Page Organizer

**Shown after file upload** for tools in `PAGE_LEVEL_TOOLS`:
```
'split', 'rotate', 'organize', 'crop', 'page-numbers',
'watermark', 'sign', 'redact', 'ocr',
'ai-summarize', 'translate', 'repair', 'edit'
```

**PageOrganizer** (`page-organizer.js`) renders a thumbnail grid from the PDF:
- Each tile shows a page thumbnail (rendered async via `PdfPreview`)
- Per-page actions: Rotate (+90°), Delete
- Global toolbar: Rotate All (+90°), Reset
- Drag-and-drop reordering (mouse + touch + keyboard)
- State stored in `pages[]` array: `{ id, originalIndex, rotation }`

**LivePreview Engine** (`live-preview.js`, v6.0) mounts for tools that show real document previews:
```
word-to-pdf, excel-to-pdf, pdf-to-word, pdf-to-excel,
background-remover, translate, ai-summarize, edit,
pdf-to-powerpoint, powerpoint-to-pdf, html-to-pdf, ocr,
scan-to-pdf, repair, word-to-excel
```

## Processing Overlay

Triggered when user clicks "Process" button (calls `processFiles()`):

```
1. Re-entrancy guard (_processingInFlight) prevents double-click
2. Usage limit check (UsageLimit.canUse())
3. File size re-check (100 MB hard cap)
4. PageOrganizer integration: getEditedPdf() if grid has changes
   → Rotate tool safety net: #opt-degrees reset to '0'
5. showProcessing() overlay displayed
6. clientSide path:
   a. Build opts from DOM (#opt-degrees, #opt-range, etc.)
   b. tryWithRetry(toolId, files, opts)
      → window.BrowserTools.process() [intercepted by RuntimeAdapters/RotateRuntime/etc.]
      → AdvancedEngine wraps with retry, memory guards, quality scoring
   c. On success: OutputValidator.check() validates result
   d. showStatus('success', ...) with download URL
7. Server fallback (if clientSide fails or tool.clientSide === false):
   a. Build FormData
   b. POST to tool.apiEndpoint (/api/merge, /api/compress, etc.)
   c. Response: PDF blob → download link
```

## Session Flow

```
1. User arrives → auth-ui.js checks ilovepdf_token cookie
2. If valid JWT: show profile chip (name + plan badge)
3. If invalid/missing: show "Sign Up / Log In" buttons
4. Auth modal: Email/password or Google Sign-In (if Firebase configured)
5. On successful auth: JWT cookie set (httpOnly, 30-day expiry)
6. Usage limits: per-session + per-day tracked server-side (usage_log table)
7. File state: persisted in sessionStorage + IndexedDB (ToolState) for refresh survival
```

